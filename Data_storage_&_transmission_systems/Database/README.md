# Практическое задание с самопроверкой по лекции "Базы данных, их типы"

## Задание 1. СУБД

Кейс
Крупная строительная компания, которая также занимается проектированием и девелопментом, решила создать правильную архитектуру для работы с данными. Ниже представлены задачи, которые необходимо решить для каждой предметной области.
Какие типы СУБД, на ваш взгляд, лучше всего подойдут для решения этих задач и почему?
1.1. Бюджетирование проектов с дальнейшим формированием финансовых аналитических отчётов и прогнозирования рисков. СУБД должна гарантировать целостность и чёткую структуру данных.
1.1.* Хеширование стало занимать длительно время, какое API можно использовать для ускорения работы?
1.2. Под каждый девелоперский проект создаётся отдельный лендинг, и все данные по лидам стекаются в CRM к маркетологам и менеджерам по продажам. Какой тип СУБД лучше использовать для лендингов и для CRM? СУБД должны быть гибкими и быстрыми.
1.2.* Можно ли эту задачу закрыть одной СУБД? И если да, то какой именно СУБД и какой реализацией?

1.3. Отдел контроля качества решил создать базу по корпоративным нормам и правилам, обучающему материалу и так далее, сформированную согласно структуре компании. СУБД должна иметь простую и понятную структуру.
1.3.* Можно ли под эту задачу использовать уже существующую СУБД из задач выше и если да, то как лучше это реализовать?
1.4. Департамент логистики нуждается в решении задач по быстрому формированию маршрутов доставки материалов по объектам и распределению курьеров по маршрутам с доставкой документов. СУБД должна уметь быстро работать со связями.
1.4.* Можно ли к этой СУБД подключить отдел закупок или для них лучше сформировать свою СУБД в связке с СУБД логистов?
1.5.* Можно ли все перечисленные выше задачи решить, используя одну СУБД? Если да, то какую именно?

Приведите ответ в свободной форме.

## Ответ

1.1. Реляционная СУБД. Финансовые данные требуют строгой схемы, ACID-гарантий, целостности и сложных аналитических запросов.

1.1. Использовать API кэширования «ключ–значение»: Redis или Memcached — хеши/пароли вычисляются один раз, результат кладётся в кэш и переиспользуется без повторных вычислений.

1.2. Лендинги и CRM. Для лендингов нужны быстрая запись потока лидов и гибкая структура форм — документо-ориентированная NoSQL: MongoDB. Для CRM — тоже документная или классическая реляционная СУБД.

1.2. Да: MongoDB (или любая документная СУБД) закроет и приём лидов с лендингов, и хранение в CRM — за счёт гибкой схемы документов и высокой скорости записи.

1.3. Графовая СУБД: структура компании — это иерархия и связи между подразделениями, документами и ролями.

1.3. Да: базу знаний можно реализовать в PostgreSQL — таблицы «сотрудники/отделы», «документы», «связи» и поисковые полнотекстовые индексы. Либо MongoDB, если данные слабоструктурированы.

1.4. Графовая СУБД: маршруты — это граф дорог и узлов, а быстрые обходы связей — профильная задача графовых СУБД.

1.4. Да, подключить можно: закупки завязаны на те же объекты, поставщиков и маршруты. Логично объединить в одном графе (общие сущности: склады, объекты, материалы), а для специфичных закупочных данных (договоры, тендеры) завести отдельные узлы/подграф, либо отдельную реляционную СУБД.

1.5. Да, PostgreSQL, с оговорками по производительности на графовых задачах. Это компромисс: меньше инфраструктуры, но часть задач решается не оптимально.

## Задание 2. Транзакции

2.1. Пользователь пополняет баланс счёта телефона, распишите пошагово, какие действия должны произойти для того, чтобы транзакция завершилась успешно. Ориентируйтесь на шесть действий.
2.1.* Какие действия должны произойти, если пополнение счёта телефона происходило бы через автоплатёж?

Приведите ответ в свободной форме.

## Ответ

2.1. Пополнение баланса телефона:

    1. Проверка баланса карты/счёта плательщика и лимитов.
    2. Списание суммы со счёта плательщика.
    3. Фиксация списания со стороны банка/платёжной системы.
    4. Передача платежа оператору связи.
    5. Зачисление суммы на баланс телефона абонента.
    6. Подтверждение операции пользователю.


2.1*. Автоплатёж. Добавляются шаги до транзакции:
    1. Наступление события (порог баланса или дата)
    2. Проверка валидности привязанной карты и согласия пользователя
    3. Проверка лимитов автоплатежа
    4. Далее те же 6 шагов.

Если проверка не пройдена (нет средств, карта просрочена) — транзакция не стартует, фиксируется ошибка и уведомление пользователю.

## Задание 3. SQL vs NoSQL

3.1. Напишите пять преимуществ SQL-систем по отношению к NoSQL.
3.1.* Какие, на ваш взгляд, преимущества у NewSQL систем перед SQL и NoSQL.

Приведите ответ в свободной форме.

## Ответ

3.1. Пять преимуществ SQL-систем:

    1. Строгая схема и целостность данных (ACID, ограничения, внешние ключи).
    2. Декларативный язык запросов SQL — стандарт де-факто, зрелые оптимизаторы.
    3. Поддержка сложных запросов: JOIN, агрегации, оконные функции, подзапросы.
    4. Транзакционность и надёжность — критично для финансовых и учётных систем.
    5. Репликация, бэкапы, инструменты, большое число специалистов и стандартов.

3.1*. NewSQL сочетает плюса обоих миров:

    горизонтальная масштабируемость как у NoSQL (распределение по узлам, шардирование «из коробки»);
    при этом полная ACID-транзакционность и SQL-совместимость как у классических реляционных СУБД;
    высокая отказоустойчивость (репликация по консенсусу, устойчивость к отказу узлов и датацентров);
    автоматически решают проблему «сначала масштабируемость, потом уже транзакции», на которой приходилось выбирать между SQL и NoSQL.

## Задание 4. Кластеры

Необходимо производить большое количество вычислений при работе с огромным количеством данных, под эту задачу выделено 1000 машин.
На основе какого критерия будете выбирать тип СУБД и какая модель распределённых вычислений здесь справится лучше всего и почему?

Приведите ответ в свободной форме.

## Ответ

Модель распределённых вычислений.  Данные шардируются по узлам, вычисления отправляются к данным, каждый узел обрабатывает свой фрагмент параллельно, результаты агрегируются на этапе reduce. Это даёт предсказуемое масштабирование на сотни узлов и устойчивость к отказам отдельных машин.
